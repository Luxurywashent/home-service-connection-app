# Home Service Connected Company Feature Gaps

## Purpose

Company mobile sessions are intentionally prevented from invoking legacy Luxury Wash endpoints for the capabilities below. The guards are a safety control, not a substitute feature implementation. No legacy fallback may be restored until the listed HSC API, data, and RBAC requirements are satisfied.

| Feature | Current web support | Current mobile support | Current backend support | Why Company mobile is blocked | Required HSC API | Required data model | RBAC | Recommended phase |
|---|---|---|---|---|---|---|---|---|
| Private job notes | Legacy admin workflow only | Blocked for Company sessions | Legacy local note mutations; no canonical Company mobile note route | Notes could be routed to a legacy host and expose cross-tenant/operational data | `GET/POST/PATCH/DELETE /api/mobile/v1/company/jobs/:jobId/notes` | Company-scoped job-note table with author, timestamps, edit/deletion audit | Owner/dispatcher write; technician policy explicit | Phase 1.5 / Phase 2 |
| Customer history | Legacy schedule detail only | Blocked for Company sessions | No canonical Company history aggregate | Customer history currently relies on legacy local service behavior | `GET /api/mobile/v1/company/customers/:customerId/history` | Company-scoped customer/job/payment/history relation | Member read scope; sensitive financial history manager-only | Phase 2 |
| Address and job photos | Legacy address-photo storage flow | Blocked for Company sessions | No canonical Company media contract | Legacy media URLs/storage must not receive Company traffic | `GET/POST/DELETE /api/mobile/v1/company/customers/:customerId/media` and job media equivalent | Company-scoped media metadata, signed-object references, audit trail | Owner/dispatcher write; field upload policy | Phase 2 |
| Invoice sending and checkout | Legacy invoice UI | Blocked for Company sessions | Existing finance/payment abstractions are not complete Company mobile contracts | Financial actions require canonical totals, provider controls, and idempotency | `/company/invoices`, `/company/jobs/:id/payments`, `/company/finance` | `fs_jobs`, `fs_job_payments`, invoice records, provider event log | Manager-only, dual-control/audit requirements | Phase 2 |
| Payment-performance updates | Legacy reporting mutation | Blocked for Company sessions | No verified Company performance update API | Could write operational/financial data to local legacy backend | `/company/performance/*` or derived reporting API | Company-scoped KPI snapshots calculated from canonical jobs/payments | Owner/dispatcher read; server-derived writes only | Phase 2 |
| Booking lookup and deep links | Legacy booking links | Blocked for Company sessions | Public booking exists separately from Company mobile authorization | Booking identifiers and public routes must not bleed into private Company API | `/company/bookings/:id` plus public Company booking route | `fs_online_bookings`, conversion links, public tenant slug | Company staff read; public access only with safe token/slug | Phase 2 |
| AI Receptionist | Legacy Twilio/OpenAI receptionist service | Direct route shows an HSC-unavailable state for Company sessions | Legacy local receptionist calls, logs, and webhook configuration only | Company calls, recordings, and provider configuration must not cross the legacy service boundary | `/company/receptionist/*` with Company webhook registration and call-log APIs | Company-owned phone lines, transcripts, recordings, consent, and provider configuration | Owner/dispatcher management; Team Member call-log access policy explicit | Phase 2 |

| Schedule blockers and availability | Legacy schedule controls | Existing Company roster/calendar read; blocker operations not authoritative | Legacy tRPC/async storage controls remain separate | Company user cannot safely mutate legacy blocker state | `/company/schedule-blockers`, availability API | Company-owned blocker/availability records | Owner/dispatcher write, technician availability self-service policy | Phase 2 |
| Notifications, email, SMS | Legacy notification workflow | No Company sending action | Provider-specific legacy configuration | Provider credentials/templates require Company boundary and consent controls | `/company/notifications/*` plus provider adapters | Company template/config and consent records | Owner/dispatcher only; audited sends | Phase 2 |

## Current safe behavior

1. Company calendar and Add Job use bearer-authenticated Home Service Connected resources.
2. Company New Job accepts one active Company Price Book service; the server validates ownership and derives the total.
3. Company requests that would otherwise call legacy notes, booking, history, media, performance, invoice, local schedule, Receptionist, or Locations endpoints are blocked with explicit user feedback.
4. Legacy behavior remains only for non-Company sessions while the relevant HSC capability is migrated and reviewed.

## Exit criteria before enabling a feature

Each feature requires an HSC API contract, tenant-scoped data model, RBAC rule, deterministic two-Company read/write tests, mobile contract tests, and a verified UI state for unavailable/forbidden responses. A legacy URL being reachable is not an exit criterion.
